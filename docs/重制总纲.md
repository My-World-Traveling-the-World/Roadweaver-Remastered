## 〇、一句话总纲

**旧版的钱花在三处：寻路（215s）、结构解析（74s）、15 道互相打架的纵断面 pass（质量上限）。
新版用三个数学上更优的内核一次性换掉它们：测地场（FMM）换掉逐对 A*、全局 DP 换掉 pass 流水线、弹性带换掉 8 个后处理。**

| 目标 | 旧版 | 新版目标 | 手段 |
|---|---|---|---|
| **更高效的算法** | 逐对 A\*（215 s） | N 次场求解得 N×N 矩阵（秒级） | `GeodesicMatrix` + MST |
| **更快的加载** | 门开→道路 ≈ 10 min | **≤ 3 min** | 寻路提速 + 结构枚举预筛 + DP 单遍纵断面 |
| **更高的质量** | 38× 坡罚不对称 ⇒ ±8 锯齿；15 道 pass 互相覆盖 | 锯齿 ≤ ±2；约束在求解前进入 | 真 Finsler + DP 约束化 + 弹性带投影 |

### 1.3 五个已证实缺陷 🔴（按严重性排序）

**A. 降级重搜时硬障碍完全失效（最严重）**

`ObstacleJudge.blocksPlanningObstacle` 开头 `if (mode == PENALTY) return false;`，而
`RawPathSearch.searchWithHardBuildingObstacles` 的降级路径退出 HARD 作用域后 mode 回落 PENALTY
⇒ `BandPathfinder` 的 `blocked[]` 全 false + `ObstaclePotential.fromMask` 也全 false ⇒ 软势恒 0
⇒ **等于在无障碍地图上找路，会穿村穿楼**。

**B. 弹性带会把绕障后的点拉回障碍**

`ElasticBandSolver` 全文 0 处 `ObstacleField`/投影，而 `FinslerMetric:35` 与 `ObstaclePotential:32`
都声称「硬约束由 band 投影负责」= **契约断裂无人负责**。FMM 绕开了障碍，平滑后曲线可横穿建筑。

**C. 纵断面是「旧流水线 + DP」双跑**

`TargetYComputation:458` 快照旧 15 pass 结果 + `:463` 再跑 DP（默认 DP）⇒ 默认成本 = 旧流水线 + DP。
DP 实际复杂度 `O(n·H·D²)`（D=2N+1），不是类注释声称的 `O(nH)`。

**D. 生产链上仍有 3 处旧式修复搜索**

`MountainSwitchbackPlanner`（自己的 PriorityQueue+A*，候选更好直接替换主路线）、
`CoarseHeightAwarePlanner`、`LocalRouteSearch` —— 都未被 Band/FMM 替代。

**E. `ArrivalTimeField.pathTo` 三项问题**

不查 `isPassable`（回溯可切角穿建筑）、非网格对齐坐标错位、`maxSteps` 对 BAND 完全无效。

### 1.4 三个中度问题 ⚠️

- **F** `PipelinePlanner` 三处 `fallbackMST`（合理兜底，建议加日志计数）
- **G** AB 双跑两臂都是 Band ⇒ 现有 A/B 日志不能证明「弹性带比旧 8-pass 好」
- **H** 六处文档与实现不符（`PathfinderFactory:14-22` 等，见 §6）

## 二、三个数学内核（为什么它们更优）

### 2.1 测地场替代逐对 A\* —— 解决「215 秒」

**旧版**：23 条连接各自跑 A\*，每条把同一片地形重新探索一遍。
**新版**：对每个结构节点跑**一次** Fast Marching（Eikonal 方程的 Godunov 迎风解），
得到它到全图每一点的到达时间 ⇒ N 个节点 = N 次求解 = 完整 N×N 测地距离矩阵。

- 拓扑（MST）在矩阵上**免费**做，树的边天然不相交。
- 复杂度：旧 O(连接数 × 每对 A\* 探索量)；新 O(N × n log n)。实测规模下预计 **215 s → 秒级**。

### 2.2 全局 DP 替代 15 道 pass —— 解决「质量上限」

**旧版**：先按地形算剖面，再依次贴 15 道补丁，补丁互相覆盖。
**新版**：把每一项旧能力翻译成 DP 的**求解前约束**，一次求出满足全部约束的最优剖面。

已搬：`deckFloor[]`（桥面水位下界）。待搬 6 项（见 §3 阶段 1）。

### 2.3 弹性带替代 8 个后处理 —— 解决「8 个 pass 修同一件事」

**新版**：`ElasticBandSolver` 一次成型（连续曲线 + 保形权重）。
待补：把 `ObstacleField` 投影接进迭代（见缺陷 B）。

### 2.4 真 Finsler 度量 —— 解决「38× 锯齿」

`FinslerMetric.cost(x, θ̂) = 1 + λ_grade·(∇h·θ̂)² + λ_obs·V(x)`，坡度乘方向分量、按弧长积分。
**已接上各向异性**（`88f75dd`），但只采 x/z 两轴，斜梯度交叉项仍缺（阶段 4 收尾）。

### 4.3 3 处旧修复搜索（缺陷 D）去留 —— 2026-11-14 取证后**重新界定**

审计把它们统称「三处旧 A* 残留」，逐处核调用面后**定性不同**：

| 类 | 行数 | 调用面 | 定性 |
|---|---|---|---|
| `MountainSwitchbackPlanner` | 429 | `RawPathSearch:68`（主选线）+ `:170`（隧道提示重搜）两处 | **选线候选补充**：盘山回头弯专用规划器，判据是「候选更优则替换主路线」。换它要重设计比选判据 |
| `CoarseHeightAwarePlanner` | 265 | `RawPathSearch:127` 一处 | **选线候选补充**：粗规划的 3D 高度感知候选，同上 |
| `LocalRouteSearch` | 539 | **8 个文件**：`ConflictDetector` / `LakeRiverRepair` / `StructureRepair` / `AccurateGradeRepairPlanner` / `RepairAcceptance` / `SearchBudgetPolicy` / `WaterCostModel` + 自引用；暴露 `findLocalRoute` 八个重载 + `searchLocalRoute` + `corridorTouchesWater` | **局部修复基础设施，不是残留** |

**⇒ 结论修正**：`LocalRouteSearch` 是「窗口内局部重路由」的公共设施，整个局部修复
子系统（7 个文件）都建在它上面。**它不是死代码，不能当残留删** —— 要换它等于整体替换
「局部修复」这一层，那对应总纲 S1–S7 里的 **S5「后处理降级为网络缝合器」**，是独立大工程。

所以 D 的真实范围是 **2 处（MountainSwitchback + CoarseHeightAware）**：
它们是「主路线出来后、再找一条候选并可能整体替换」的补充搜索。
要判断能不能去掉，必须先证明**新内核本身已经不会产出它们要修的那种路线**
（回头弯 / 高度不可行的粗走线）—— 而这需要真机基线（阶段 0）。
