## 二、Claude 的独特贡献（Antigravity 没有的）

1. **NEW-6 撤回**：用 Godunov 单调性证明不查 frozen 结果等价（数学严格，非 bug）
2. **NEW-2 修正**：错位最大 7 格不是 8 格（边界取整精度）
3. **N2 数学发现**：FMM 求解的度量（轴对齐对角黎曼）**不含交叉项**，与文档声称的 Finsler 度量不等价——数值正确性根本问题
4. **N1 新发现**：BandPathfinder 只测格点，缺少边级障碍检测（宽度 < step−2·clearance 的建筑会被夹过）
5. **NEW-5 数学证明**：对角方向梯度被系统性偏爱 √2−1=41.4%（从数学上量化了「之字」成因）

## 三、修复顺序（Claude 建议 + 主控裁定）

**最该立刻做的 5 件事**：
1. A + NEW-8 + 降级路径：BandPathfinder 不依赖 ThreadLocal，PENALTY 下用软势
2. NEW-3：PipelinePlanner 只调 GeodesicMatrix + MinimumSpanningTree，跳过 RoadPipeline.run 第二轮（零风险）
3. NEW-1 + NEW-2：源点不可通行时吸附或返回失败，不抛异常；全仓统一量化函数
4. FMM 预计算代价数组 + 目标早停（结果逐位相同）
5. N1 + B：BandPathfinder 做边级障碍检测，弹性带加障碍投影

**下一个排期**：N2（度量与文档不一致），需真机 A/B

**NEW-7 裁定**：`CostModel.defaults()` 的 `(cutWeight=1.0, fillWeight=0.7)` —— 旧版是硬约束（`limits.fill()` 默认 0，只降不升），重构版变成权重（`fillWeight=0.7` 填方比挖方便宜），**写反了**。修法：`fillWeight ≥ 1.0` 或不对称窗口。
