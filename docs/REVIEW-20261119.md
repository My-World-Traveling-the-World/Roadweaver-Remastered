## R1：台账读失败被当作空台账，后续写盘丢失旧完工信息（P0）

**现象与证据**

- `common/src/main/java/net/shiroha233/roadweaver/persistence/RoadConstructionLedger.java:135` 创建新状态，`:139` 读全文件，`:165` 捕获 IO/解析异常后仍返回该状态。
- 条目先积累在临时列表，解析途中坏行会阻止整个列表发布；这能避免半加载，却没有保留“未知”状态。
- 同文件 `:132` 把读取结果放进世界会话缓存；`:72` 的正常 flush 随后把这个新状态写成完整台账。
- `common/src/main/java/net/shiroha233/roadweaver/generation/DeferredInitialRoadConstructionService.java:60` 起的恢复流程依赖完工查询判断是否重新入队。因此问题不止是文件变小，还会改变后续施工决策。

探针先写入 A/B 两项、重开确认存在，使用 Windows `NOSHARE_READ` 确认真实读取抛 IOException；调用正式 `load`，解除文件锁后沿用这个状态完成 C 并 flush，再次重开：

```text
AUDIT_LEDGER_READ_FAULT first=false second=false third=true bytesUnchanged=false
AUDIT_LEDGER_PARSE_FAULT first=false second=false third=true
```

第二行是合法文件尾部增加 `entry=bad,0,77` 的独立案例。两种都证明旧完工记录被后续正常落盘覆盖。探针只写隔离临时文件，没有读写玩家存档。未现场验证玩家方块是否被重铺，不能将“可再次入队”扩写成已发生玩家建筑损毁。

**修复边界**

缺失文件、完整读取、读取失败必须分开；失败状态禁止覆盖台账，也禁止以“未完工”名义开始恢复施工。完整重读成功后才能替换状态。不能只给 flush 加只读开关而放任恢复流程重铺。保留 schema 3 和原字段。

## R2：空计划承担三种不同结果，暂时状态被永久结案（P1）

**证据链**

1. `common/src/main/java/net/shiroha233/roadweaver/worldgen/road/RoadWorldgenPlanCache.java:41` 在道路关闭时直接返回空计划；`:130` 在编译 RuntimeException 后记录 WARN，也返回空计划。
2. 同文件 `:178`、`:190` 把编译结果存入正常计划缓存，失败没有独立重试结果。
3. `common/src/main/java/net/shiroha233/roadweaver/pathlogic/PathFeature.java:108` 把空 slices 统一变成 `EMPTY_PLAN`。
4. `common/src/main/java/net/shiroha233/roadweaver/generation/LoadedChunkRoadBackfill.java:270` 把它加入 noConstruction，`:188` 发布结案。
5. `common/src/main/java/net/shiroha233/roadweaver/generation/DeferredInitialRoadConstructionService.java:192` 把区块记为无需施工并移出 pending。恢复配置本身不清除这个标记；新道路写回、显式解标或世界关闭才另有处理。

最小探针调用真实禁用入口、真实 replay 分支和真实结案 API，再开启同一配置：

```text
AUDIT_DISABLED_ROADS outcome=EMPTY_PLAN enabledAgain=true stillTerminal=true
```

该探针只为禁用分支构造最小维度身份，没有伪造地形、区块或落块成功，也没有运行服务端完整 tick。实际回填调用链另已打开源码逐段核对。编译异常的错误归类由源码证实，**真实 ServerLevel 编译故障到恢复全过程尚未集成复现**。

临时在正式 compile 内强制抛 RuntimeException，全量仍然：

```text
PASS tests=1663 skipped=0 aborted=0 failed=0
BUILD SUCCESSFUL
```

它证明该故障面没有被现有回归有效约束，不代表线上已经全部失败。

## R3：有界计划缓存之外还积累无界版本表（P2）

`common/src/main/java/net/shiroha233/roadweaver/worldgen/road/RoadWorldgenPlanCache.java:158` 的 `chunkRevisions` 与两张 LRU 独立；`:220` 对每个失效源写入 5×5 邻域。计划条目淘汰不回收版本，只有全局 invalidate 或会话结束清除。

调用真实 Session.invalidate，输入间隔 10 区块的 5,000 个源：

```text
AUDIT_REVISION_GROWTH sourceChunks=5000 revisions=125000 fullPlans=0 emptyPlans=0
```

这证明增长不受 4,096/16,384 条计划容量约束，尚未测真实 4096 预热中的堆占用与 GC。不能简单在 LRU 淘汰时删版本：在途旧编译仍需被新版本拒绝发布。

## 跨模组边界：真实门洞尚不是道路通行许可

长城真实门洞探针确认 `OWNED_VOID` 存在，但公开 `WallRoadApi.blocks(x,y,z)` 仍返回 true。它是 XZ 列保护，门洞上方屋顶也占同一列；道路适配器仍声明“道路止于墙脚”。`NegotiatedGateService` 有实现与会话装配，但两仓库生产源码没有找到其 request 的消费调用。

这是当前能力边界，**不是本轮模板替换丢失旧能力的证据**。以后若要道路穿门，应交付有方向、通行高度和有效期的通道证书，不能直接放开整列而让道路挖到屋顶/基础。尚未做三模组真实穿门验收。

## 可执行方案，按价值排序

### 1. 让台账读取失败进入明确降级状态

- 类型：**行为变更 + 测试基建**；目标：`RoadConstructionLedger`、`DeferredInitialRoadConstructionService`。
- 第一步：在同一 schema 3 下区分 missing/loaded/failed，复用真实 Windows 文件锁和坏行夹具，先把“旧 A/B 不丢、新 C 不覆盖未知索引”写成会红的回归并登记 suite。
- 第二步：台账加载失败时暂停依赖它的恢复/结案，保留原因和待重试；完整重读成功后再原子发布。
- 第三步：验证停止/重开、故障恢复和“写盘失败后重试”，保证没有新的放行空窗。
- 验收：故障期间文件逐字不变；恢复后 A/B/C 契约明确且不丢项；临时恢复旧 catch-return-empty 必须红。
- 风险与回退：降级会延迟施工；可以撤回该提交，不能用静默空状态当运行期回退。需存档副本验收，不需改存档格式。

### 2. 把区块计划计算结果与施工内容分开

- 类型：**行为变更 + 测试基建**；目标：`RoadWorldgenPlanCache`、`PathFeature`、`LoadedChunkRoadBackfill`。
- 第一步：引入内存结果 `READY / EMPTY_CONFIRMED / DISABLED / RETRYABLE_FAILURE`，先用最小端口对拍原成功计划。
- 第二步：只有确认无施工才能永久结案；关闭和故障保留重试资格、可辨识原因与限频诊断，失败不进入正常空计划缓存。
- 第三步：补禁用→启用、首编译失败→恢复、卸载→重开与同版本并发发布测试；登记 suite。
- 验收：强制全部编译失败会红；恢复后能实际铺设并完工，正常空区块不无限重试。
- 风险与回退：重试风暴和重复施工；需预算、退避和台账保护，逐个调用入口接线。需普通世界故障恢复验收；依赖方案 1。

### 3. 修复整段墙的接口相位契约

- 类型：**行为变更**；目标：长城 `ImportedRibbonSection`、端口/连续墙段契约。
- 第一步：补真实端口第 1～100 格、直线/斜线、双端点和跨区块产物守卫，尤其钉住 24→25 格。
- 第二步：整段连续墙冻结同一相位原点和方向，双端接口约束冲突时显式规划过渡，不能在固定 24 格处回到无关的全局里程。
- 第三步：四方向、五件建筑、非整格段缝以及反向施工对拍；再看普通世界连续视觉。
- 验收：马道/腰线保持，循环不中断，两端仍缺结尾；“远离端口全缺”变异必须红。
- 风险与回退：可能改变已规划 v2 后续墙列，必须核对冻结配方和续建边界；依赖长城报告中的详细约束。需真机。

### 4. 长城投影改为保持精确定点语义的空间索引

- 类型：**性能 / 行为等价**；目标：`ImportedRibbonProjection`、`RealizationPlanner`。
- 第一步：保留扫描实现作为测试参照；扩展原型到五件×四向、同距、反向、折返与段缝。
- 第二步：按包围盒下界剪枝，保持原 Q8 运算、端点延长和同距原站序；每个不可变窗口只建一次索引。
- 第三步：测节点访问、叶边检查、建树分配、窗口工作集，再采真实预热和回填尾延迟。
- 验收：本轮 63,057 列已逐字段一致；全面对拍仍需完成。当前边循环数 16,331,763，原型精查边 390,061；后者不包含树节点访问，不能当成总耗时倍数。
- 风险与回退：密集折返最坏仍可能扫很多边；纯性能提交可独立撤回。需真机量收益。

### 5. 长城建筑判定与完整体素编译分离

- 类型：**纯重构 + 性能**；目标：`RealizationPlanner`、`ImportedTowerBody`、窗口内组件所有权。
- 第一步：拆出只读建造证书，包含地基、保护、材质与失败原因，所有投票 cell 使用同一证据。
- 第二步：完整体素仅由发布 cell 物化一次；短期若缓存完整结果，必须带窗口/配方/高度/保护证据键和明确内存额度。
- 第三步：逐体素、实体、战利品、哈希、失败原因对拍，验取消/换代不复用旧证据。
- 验收：本轮澄海楼夹具编译 2 次、输出 1 份、累计生成 234,854 个体素项；目标同样输出只进行 1 次完整编译。
- 风险与回退：证书与实际产物漂移；分层提交，禁止减少地基/保护检查来换快。需真机长墙工作集验证。

### 6. 有界道路版本跟踪与长城批量保护发布

- 类型：**性能 / 行为等价**；这是两个独立提交，不能混成一次跨仓库大改。
- 道路步骤：先抽取带版本发布协议；记录活跃编译与缓存引用，只有两者都不存在时回收局部版本；补旧计算晚到、清空和换代交错负控。
- 长城步骤：`WallPlanSupport` 按 chunk 收集独立 XZ 位图，`WallRoadGuard` 单次合并一块；修正 `WallBodyBackfill` 把体素数报成列数的口径。
- 验收：道路失效版本工作集有界且旧结果不复活；长城所有保护查询与逐体素发布完全相同，含 owned air 和边缘 padding。
- 风险与回退：并发版本 ABA、遗漏空气列保护。各自独立撤回；需要真实驻留和锁竞争测量，不能预报帧率。

### 7. 长城建筑高度预检与失败粒度

- 类型：**行为变更**；目标：`HeightContractPlanner`、站点状态/后续墙段决议。
- 步骤：使用实际素材最高偏移预检可容纳性；在站点级记录超界并确定一致绕过/断头结果；重新计算受影响高度和墙段，邻窗必须共享冻结结论。
- 验收：地表 280/上界 320 的反例有明确局部原因，其余合法站点继续规划；不压低“最高点+15”、不截屋顶、不填门洞。
- 风险与回退：跨段决议一致性。当前只证实高度规划器抛错，整个启动生命周期后果未验证；先补集成故障测试，需真机高地。

## 架构判断与检查过的方向

目前没有证据要求换掉 FMM、DP、弹性带或再建一个总调度器。更有价值的拆分是**完整读取状态、计划计算结果、组件证书、不可变窗口投影、发布所有权**；每一层都有上面的失效场景与产物验收。

- 扫描道路 713 个、长城 262 个生产 Java 文件，去注释/空行后无文件超过 1000 有效行。长城 `ProductionSession` 约 927、`GreatWallCommands` 约 902，职责仍值得收敛，行数达标不是充分条件。
- 道路回归 suite 按完整多行 `selectClass` 表达式核对，243 个类选择，未发现带 JUnit 注解却漏登的测试类。
- 既有稀疏拓扑、施工游标、台账分段计时、三通道采样和线程许可没有在本轮被替换。跨 tick 施工仍缺现场 p99；不能把已有同步游标当成已经解决主线程长尾。
- `crossing`、双平滑最终裁决、QualityGate 标定、长桥正弦和废弃 GPU 精确采样保持用户已定口径。
- 未做新一轮旧仓库所有功能的逐项真机复验，也未测实际 FPS、MSPT、整合包 4096 工作集或启动时间。
