## 一、配置分层：`SubConfig` → `ModConfig` → `ConfigService`

**`SubConfig` 契约**：[SubConfig.java](roadweaver/common/src/main/java/net/shiroha233/roadweaver/config/SubConfig.java)（12 行），`sanitize()` `:8` + `snapshot()` `:11`。无版本号、无 key、无注册表——纯结构约束：11 个 `*Config` 必须同时提供「就地夹取」与「返回副本」，`ModConfig` 才能级联。

**`ModConfig` 聚合**：[ModConfig.java](roadweaver/common/src/main/java/net/shiroha233/roadweaver/config/ModConfig.java)（243 行）。10 个子配置字段 `:13`–`:23`（`structurePrediction`/`planning`/`terrainProfile`/`pathfindingCost`/`roadAppearance`/`bridge`/`performance`/`roadsideStructure`/`roadsideVillage`/`client`）、`snapshot()` `:37`、`sanitize()` `:52`、约 60 个转发 getter 起于 `:76`。**算法核心**：`sanitize()` **先补 null 再级联**（`:53`–`:61` 补、`:63`–`:72` 级联），含 null 字段的配置不会 NPE；`snapshot()` 每项走 `x == null ? new XxxConfig() : x.snapshot()`，快照永不 null。**每个字段都有 `= new XxxConfig()` 字段初始化式——这是「键缺失时取什么值」的唯一真值来源。**

**⚠️ 0.8.345 坑**：`ConfigService.get()` 返回**全局单例本身**（`ConfigService.java:100`）。历史消费方（`RoadConstructionVolumePlanner.Context`）对它调 `sanitize()`，会在 **worker 线程改写全局配置**、与界面 setter 丢失更新，还在最终校验热路径上。`snapshot()` 就是为此新增的逃生口（`:25`–`:36`）。

**`ConfigService` 读写**：`GSON`=prettyPrinting `:26`、`INSTANCE` 为 **`volatile`** 静态单例 `:37`、`load()` `:41`、`save()` `:87`、`get()` `:100`、`markDirty()` `:178`（=`save()`）。`load()`（`:41`–`:85`）：文件存在 → parse → 非 null 则**先赋 `INSTANCE`** 再跑两处迁移（`:56`–`:57`）；不存在 → `save()` 落默认（`:64`）；解析异常 → warn + 保留默认；最后**无条件 `sanitize()` 且 `catch (Throwable)`**（`:67`–`:71`）。用 `volatile` 而非 `synchronized` getter 的理由见 `:30`–`:36`：热循环每 tick 都读，代价是**读方可能看到夹取中途的值**，靠幂等兜住。

**派生聚合体 `RoadGenerationConfig`（不持久化）**：同目录 [RoadGenerationConfig.java](roadweaver/common/src/main/java/net/shiroha233/roadweaver/config/sub/RoadGenerationConfig.java)（129 行）由 `from(ModConfig)` `:24` 拍平 11 个值，**不在 `ModConfig` 里、不写进 `roadweaver.json`**，`tunnelClearHeight = 5`（`:16`）、`bridgeRampSegments = 4`（`:22`）还是硬编码副本；消费点 `RoadPathCalculator:379`、`Road.java:103`。

## 二、持久化格式：**GSON 字段名就是配置键**

**没有 DTO、没有 `@SerializedName`、没有显式 key 表**。`save()`=`GSON.toJson(INSTANCE)` `:94`（**先 `sanitize()` 再落盘**，`:93`），`load()`=`GSON.fromJson(root, ModConfig.class)` `:53`，落盘走 `FileStorageIO.writeStringAtomic`（tmp + `ATOMIC_MOVE`，[FileStorageIO.java](roadweaver/common/src/main/java/net/shiroha233/roadweaver/persistence/files/FileStorageIO.java) `:19`/`:41`）。磁盘结构就是两级字段名：一层=`ModConfig` 字段名，二层=子配置字段名。

### ⛔ 硬约束一：**配置键名 = Java 字段名，一个都不能改**

| 改动 | 后果（GSON 默认策略） |
|---|---|
| **改字段名** | 老键被**静默丢弃**，新字段回落字段初始化式 = **玩家设置全丢且无报错**；下次 `save()` 旧键从磁盘永久消失，**不可恢复** |
| **改子配置对象字段名**（`pathfindingCost`→`pathfinding`） | 同上，且**整段 59 键一次性丢失** |
| **删字段** | 老键变死键（GSON 忽略未知键），无害；但先删后加回会让期间存的档拿不到值 |
| **加字段** | **安全**——老配置无此键 → 取字段初始化式，下次 `save()` 自动补上。这就是「加键不用写迁移」的原因 |

唯一兜底是 §八 的两处显式迁移，其存在理由正是「Gson 只在键存在时覆盖字段」故改默认常量无效（`ConfigService.java:190`–`:201`）。**除此之外改键名 = 丢配置，没有任何代码会救你。**

### ⛔ 硬约束二：枚举以 `name()` 存盘，常量名不能改
`planning.planningAlgorithm`、`terrainSamplingMode`、`terrainProfileMode`、`pathfindingCost.pathfindingAlgorithm` 按 `Enum.name()` 序列化（[TerrainSamplingMode.java](roadweaver/common/src/main/java/net/shiroha233/roadweaver/config/sub/TerrainSamplingMode.java) 22 行）。改常量名 → 老配置反序列化抛异常 → **整份 `load()` 落进 `catch (Exception)` → 全部配置回默认**（`:60`–`:62`），比单键丢失严重一个量级。

## 八、配置迁移与校验

**`sanitize()` 链**：`ModConfig.sanitize()` `:52` → 10 个子配置各自 `sanitize()`。**幂等**是 `volatile INSTANCE` 敢裸读的前提。三种口径风格（移植时别混）：① `Math.max(min, Math.min(max, v))` 最常见（`RoadAppearanceConfig:62`–`:78`）；② **越界回落出厂值**而非夹边界（`TerrainProfileConfig.clampCut`/`clampFill` `:76`/`:81`、`clampMultiplier` `:86` 的 `!Finite || <0.25 || >4.0` → 回落；`RoadsideVillageConfig.finiteClamp` `:44`）；③ **`null` → 重建/填默认**（`ModConfig:53`–`:61`、`StructurePredictionConfig:24`–`:28`、`RoadGenerationConfig:63`–`:66`）。

夹取特例：`roadWidth` 夹 `[0,ROAD_WIDTH_MAX]` 后**强制奇数**（偶数 +1，越上限则 −1；footprint 是中心线胶囊，半宽 2.0 覆盖 −2..+2 共 5 格，偶数无法表达，`RoadAppearanceConfig:66`–`:72`）；`bridge.shareRadius` 夹 `[0,96]` 且 **`0` 合法（=关闭）不能被夹成 1**（`BridgeConfig:52`，`ConfigKnobHonestyTest:62` 钉住）；`bridge.clearHeight` 夹 `[0,16]`、`0` = 跟随 `tunnelClearHeight`（`BridgeConfig:26`–`:33`）；`culvertMaxStations`/`culvertMaxWaterDepth` 夹 `[1,16]`/`[1,4]`（**下限 1，不允许 0**，`RoadAppearanceConfig:148`/`:150`）；`setRoadWidth` **不夹取**，必须靠 `sanitize()`（`:126`）；`RoadGenerationConfig.effectiveRoadWidth` 夹 `[1,ROAD_WIDTH_MAX]`（**下限 1 不是 0**，口径不一致，`:53`）。

**迁移 #1：坡罚刻度重标定（0.9.063）**。`ConfigService.migrateLegacyGradePenaltyScale(JsonObject root, ModConfig loaded)` `:202`，`load()` `:57` 调用。旧值 `LEGACY_SOFT_GRADE_PENALTY`/`LEGACY_HARD_GRADE_PENALTY`，新值 `DEFAULT_SOFT_GRADE_PENALTY = 780.0`/`DEFAULT_HARD_GRADE_PENALTY = 39000.0`，比较 `Math.abs(x−legacy) < 1.0E-9`（`:210`/`:215`）。**算法核心：读的是 `root`（原始 JSON）而非 `loaded`（GSON 结果）**———GSON 只在键存在时覆盖字段，无法区分「玩家显式写了 600」与「字段默认就是 600」；类型不对用 `readNumber()`（`:223`）吞异常。**必须有它**：`save()` 整份写盘，任何装过 ≤0.9.062 的实例都显式写着旧值，只改默认常量等于标定没做（`:190`–`:201`）。只改内存，下次 `save()` 落盘，**幂等**。
