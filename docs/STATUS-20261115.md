## 三、之前做过的重制功能（当前仍成立）

### 1. 规划与寻路

- 旧 A* 寻路器四类与旧规划器六类已删除。
- 默认且唯一规划枚举为 PIPELINE，寻路枚举为 BAND；旧值只做配置兼容。
- 网络拓扑：N 次场求解 → GeodesicMatrix → MinimumSpanningTree。
- 单路：FastMarchingSolver → pathTo → ElasticBandSolver.smooth。
- FinslerMetric.cost 已由 FMM 按 x/z 方向实际调用，不是死方法。
- 已完成坐标统一、边级障碍采样、源点不可达容错、FMM预计算与目标早停。
- 弹性带已做硬障碍投影；曲线首尾已强制对齐。
- PipelinePlanner 不再白算完整曲线；QualityGate 已接回生产做报告。
- level=null、采样失败、pipeline 异常仍有直线距离 fallbackMST，并带 WARN。

### 2. 纵断面与坡度

- 全局 DP 目标函数含挖填代价、施工窗口、一阶/二阶坡度、站钉、桥面下界、隧道覆土。
- prefer-cut 已修正为填方比挖方贵。
- 300 组小规模暴力枚举对拍。
- ProfileFallback 无状态、确定性、幂等，承担不可行/异常回落。
- DP 成功跳过旧事后 pass 编排块；不可行/异常不再跑该块。
- **但旧 RoadGradePlanner 并未全生产退出**：
  stabilizeSurfaceProfile 仍无条件先跑，RawPathSearch、AccuratePathHeightResolver、
  AccurateGradeRepairPlanner 也仍调旧工具。
- 批1 DONE 的准确含义：默认 DP + 旧编排块退场 + 标记/台账完成，不是物理删空。
- SurfaceGradeLimits 已抽成顶层类型；端点锁定已有10个分支钉子。

### 3. 桥隧与施工

- ModeDpSolver 在同一 DAG 上联合求 GROUND/BRIDGE/TUNNEL 与高度，200组暴力对拍。
- ProfileAbObserver.observeModes 与 ModeDpBridge/[SPAN-AB] 都只观测。
- 生产桥隧决策仍来自 PathSpanExtractor。
- BuildFrame key = 中心线指纹 + 桥配置 + 精确跨度内容；copyForUser 深拷贝。
- PathFeature 与 RoadConstructionVolumePlanner 的 terrainSamplePositions/visit 共用缓存。
- 桥改隧道、桥段移位两个负控均已实证。
- promoteRuntimeBridges、planGrade、plannedBridge、三态保护列、隧道洞身约束继续保留。
- BuildPlan/BuildPlanCompiler 已因接线成本过高删除，不是待接线功能。

### 4. UI、配置与持久化

- 配置界面已拆分区；当前入口121行、13 Section。
- 9 dock动作、15手绘键位、四UI区与中英键有守卫。
- ConfigKeyTable 接进生产；未生效/废弃项必须在 UI 如实承认。
- 10个旧 A* 死配置旋钮已物理删除。
- 存档 schema、跨mod契约、长桥正弦弯、村庄包围盒判据未破坏。
- 历史196键零丢失属于当时对账，当前精确数量需要重采，不直接外推。

### 5. 质量工程与发布

- 已有架构分层/依赖ratchet、死代码、重算热点、S5文件/方法台账、Legacy台账、
  UI功能、维护性、测试注册、Gradle入口、配置诚实性等守卫。
- 当前 S5 方法台账：15 DELETE_WITH_LEGACY + 18 LEGACY_ONLY = **33/39** 待旧链路下线后删除。
- 发布件必须取 `fabric/build/final`，内嵌5 jar 且含 roadweaver-api.jar。
- 当前发布台账在 [`RELEASES.md`](RELEASES.md)。
- 新修复完成后的回滚是整包回滚 jar，不是把新算法切回旧版。

### P1：核心功能收尾

- **批2**：`groundBanned` 的循环论证**已解除**（2026-11-15）——
  新增 `GroundBanSources`，禁地面掩码改由「水面（`PathTerrainField`）+
  保护区（`StructureAvoidanceCache`）」两条**与旧判定无关**的物理事实构造，
  `isCrossing` 降级为日志对照量。8 个钉子 + 负控实证。
  两臂（剖面 AB 与桥隧 AB）现已**共用同一份掩码**，不再一臂用独立来源、
  另一臂用 `isCrossing`（那样数据不可比）。
  **仍未做**：
  ①「已有公路」来源。已做独立核查，结论是**不要用 plan cache + densityStamp**：
  它的语义是「已规划并落盘」而非「已建成」，而且**桥隧段的 stamp 是空的** ——
  恰好在最需要「已有公路必须架桥」的地方查不到。可行替代是
  `RoadShardStorage.hasRoadInRect`（方块级精确、覆盖桥隧段、无配置门控、纯内存微秒级），
  但需配套：按 `ownerA2dKey/ownerB2dKey` 自排除当前路、每次规划只建一次判定数据、
  端点挖洞避免路口变桥头、以及把 `RoadChunkStore.readOnlyDegraded` 暴露成
  `road=ok/absent`（否则静默返回空与「确实没路」同形）。**排期属批 4**。
  ②`ProfileDpSource.solve(terrainY, isCrossing, ...)` 的 crossing 输入
  **仍来自旧判定** —— 纵断面的桥段钉直线还依赖旧 spans；
  它需要「路跨路」这一来源，同样依赖上面 ① 的已有公路索引。
  ③ModeDpSolver → spans 的正式回写。
- **N2**：完整 Finsler 斜向交叉项，必须 A/B。
- **候选搜索**：MountainSwitchbackPlanner/CoarseHeightAwarePlanner 的去留需真机基线；
  LocalRouteSearch 明确保留。注意这批字段（`heuristicWeight` / `aStarStep` 等）
  仍被候选搜索与局部修复读取，**不是死键**，不能因为「A* 时代」就删。

### P2：批次、架构与指标债

- **单文件 1000 行硬约束（2026-11-15 已清零）**：原先 3 个文件贴线或超限 ——

  现在全部 ≤1000，主源码零超标。
  **但还有 2 个贴线文件（下次改之前必须先拆）**：`RoadSnapService` 995 行、
  `StructureAvoidanceService` 998 行 —— 加任何东西就会破 1000。

- 批3继续逐项分类桥体/施工职责，不能因首项修复就标 DONE。
  **2026-11-15 核实出的批 3 真实形态**：`pathlogic/bridge` 14 类 2831 行
  **全部在生产路径上，没有一个是死代码**；`pathlogic/construction` 4 类 1474 行
  不是它的替代品，而是**施工骨架**（缓存 / 体积 / 铺路 / 巨树预留）。
  两者是协作关系 ⇒ 批 3 不是「删旧实现」，而是「让施工层接管并去重」。
  其中最明确的债：**体积规划 `RoadConstructionVolumePlanner` 只被
  `FinalRoadStructureValidator`（落盘前校验）使用，而实际施工 `PathFeature`
  走自己的坡度/铺设逻辑** ⇒ 「校验算的方块」与「施工改的方块」是两套事实，
  一旦分歧就是「校验通过但实际铺错」。属批 3/批 7 交界，改动面大，需单独设计。
- **批4–7 的目标包（`roadnet`/`geometry`/`avoidance`/`validate`）在当前仓库里尚不存在**，

- **批 5 的真实范围比台账小得多**：`postprocess/` 13 个文件 5621 行里混着两种职责，

  - **接线与合并（批 4）**：`RoadSnapService`(995)、`NetworkReuseMerger`(800)、
