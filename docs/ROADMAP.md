# RoadWeaver 重制版的下一阶段

当前代码状态见[开发现状](STATUS.md)，旧版证据见[功能对照](FEATURE-PARITY-CHECK.md)。本路线讨论还没完成的事。

旧版用来查施工承诺和功能退化。重制版的评价标准是：更常交付可建、可通行、能共享关键基础设施的路网；减少无用采样、寻路和区块任务等待。

| 范围 | 旧版 | 重制版要怎么超越 |
|---|---|---|
| 选线 | 势场 A* 对每条路扩展节点，地形、群系、避让、优惠和形状旋钮混在步进代价里，最后再修形 | 保留 FMM、DP 和弹性带；区分硬禁行、软水域成本和实际施工代价 |
| 选网 | 成路后再判并排、共用、合流 | 测地拓扑先选端点边，但 PipelinePlanner 传入 ObstacleField.NONE。下一步应让能否建造、能否共用渡口影响入选 |
| 施工 | 模板和程序化建造桥梁、隧道、陆地铺设与 NETWORK_REUSE | 两版调用均存在，复用既有建造能力，把同一份终态路线及区块占地交给施工 |
| 性能 | 历史的 215 秒来自旧版逐路搜寻的现场记录 | 不能与本轮纯内核毫秒数直接比较。应在同一存档、同一组连接拆分采样、拓扑、单路、区块编译和落块耗时 |

## 推荐顺序

1. **坐标口径（已完成离线验收，待真机）**。平地、step=8、源 (8,8)、目标 (34,19) 原先回溯首格偏到 (10,11)。现按真实采样格回溯，平滑后接独立校验的短边；负坐标、正反向、同格、保护列和对齐点序均有回归。见 [HANDOFF 第 6 轮](HANDOFF.md)。
2. **按可建性选网（粗格影子已接线，真实施工证据待采）。** PipelinePlanner 用高度和轴向坡度选树，Road 在后段才做桥隧、挖填和保护校验。同种子开启 `-Droadweaver.buildabilityShadow=on` 收集候选的测地成本、湿格、高程偏差和可共享湿格；只评入选边和有限候补，原拓扑不变。首批夹具已覆盖「近但难建」「两线能共用渡口」。现场比较施工后可通行道路、绕行、平行桥与挖填量；没有实际修建结果前不启用补边或换边。
   - 粗拓扑仅复用现有高度图，高度差只能作为湿列代理；`AsyncPlanningOps` 先产出 `incoming`，随后才准备结构快照，所以当前生产影子不出完整施工排名。日志 `gradeOnlyOrder` 仅按首尾弦线的高程偏差做对照；共享湿格不是共用桥梁的确认。以后应以同一连接标识关联后段的实际施工、保护校验，再决定要不要对有限候补做对应精算。
   - 每批最多评 12 边、4 条候补，按源复用回溯场，并按格数 × 最坏求解次数限额；超出预算写明原因。回归对照了开关关闭、评分成功和评分异常的相同拓扑及顺序。
3. **只决定一次横向几何（同路径影子已接线，待真机 A/B）。** `-Droadweaver.landRelaxShadow=on` 仅在影子产物跳过第二次陆地 relax，仍执行桥线拉直、样条、桥头加密与道路宽度栅格化，施工长桥正弦不动。日志 `[LAND-RELAX-SHADOW]` 比较占地列差异、最大站距、保护碰撞/缺口及转向指标；快照缺失单列。影子结果未进入后续修坡、保护回退或施工；必须看同种子产物和桥头落块，才能切默认。
4. **盯尾延迟（FMM 队列已优化，真实加载待测）。** FMM 用两个原始数组复用队列，保留原出队顺序和回溯。对拍和分配数据见 [HANDOFF 第 9 轮](HANDOFF.md)；`-Droadweaver.fmmTimings=on` 记录冻结格、总入队数、峰值、预计算和传播时间。随后在首次生成、重开和 Chunky 同跑分别采各阶段 p50/p95、区块任务最长等待；若采样主导，优先在同一上下文共享只读瓦片。只有数据指向候选图过大才试分区和稀疏邻域，并复核合法替代边和连通性。
   - 延迟施工已用加载事件唤醒、限额轮转补漏，每轮最多 32 个提示键加 128 个轮询键；施工限额仍为 8。离线一万个待处理、只有一个已加载时，旧代码必须查 10,000 个键，新调度带提示用 129 次查询并先命中已加载键。真机用 `deferredChunkTimings` 看候选阶段尾延迟，再为入队到首次可施工、到竣工分别采等待时间；重点验无玩家 Chunky 和重开早于入队的加载事件。
5. **分开道路身份和施工完工（离线重开对拍已做，重铺策略待存档）。** `-Droadweaver.constructionContentShadow=on` 在成功写入后报告同一道路键的剖面、跨度、落列和面层变化。临时 NBT + 台账重开已证：三类变更可区分，原完工键和 schema 3 原样保留。下一步用存档副本区分「确实需要重铺」「已有区块需要拆除或保留」「旧台账缺历史内容」；在验证前不自动作废现有完工。
6. **更完整的方向代价（已量化，候选公式待对照）。** 45° 旋转后，合成 25% 坡面上坡和沿等高线，当前 FMM 都报每格 1.0486；完整方向公式分别是 1.0625 与 1.0000。窄山口旋转后，FMM 场值增加但回溯仍在走廊。先离线比较候选迎风模板的硬避让、曲率、坡度、施工成本和耗时，再决定是否做现场 A/B；当前不改求解公式。
7. **旧版的两处选线差异（离线补齐，待终态与真机对照）。** BAND 已按道路宽度对巨树预留做点和跨边硬约束，并用已有水柱、河海标记恢复 WATER/OTHER 相对成本。施工实时保护继续有效；粗拓扑、后处理改线和真实桥长留待独立对照。见[功能对照](FEATURE-PARITY-CHECK.md)。

本轮保持 ProfileDpSource.crossing、跨度回写默认值、长桥正弦、村庄包围盒、QualityGate 阈值与存档格式。纯内核数据不外推世界加载和帧时间。现场样本应分首次生成、已有存档重开、Chunky 同时运行；分别记录计划、通过校验及实际落成的道路。

## 下一轮能离线推进的三项

1. **延迟施工复用同轮已查结果（保留功能，优先验证卡顿）。** `DeferredInitialRoadConstructionService` 判加载和完工，`LoadedChunkRoadBackfill` 再查后拿 `RoadChunkPlan`，`PathFeature` 又请求计划。先给三段分别计数与计时，再试在同一调度调用内传递已加载区块和带版本的计划；保护跨度写回换了版本仍须重取。另测 `RoadConstructionLedger.flush` 对完成条目全量排序、写盘的成本；若确认拖长主线程，再做按版本串行落盘和停服封账，保持 schema 3 与失败重试。离线验收要覆盖写入失败、重开、保护跨度变化和不主动加载区块。
2. **用空间桶筛测地候选，再把稀疏边交给 Kruskal（重构内核）。** `GeodesicMatrix` 分配方阵并多次遍历节点对，`MinimumSpanningTree` 又扫一次。有限长时，以限长作为 X/Z 桶边长，只枚举相邻九桶，再保留现有精确三维判定；按原顺序处理相同权重的边，无限长继续全对枚举。900 点合成原型将探测数从 404,550 降到 8,798，准入仍是同一组 3,119 对；密集样本没有减少。先对拍准入边、双向测地权重、森林顺序、分量和产物；未测 Java 集成耗时。
3. **校验折返、栅格化和合并后的真实占地（保留与重构的交界）。** `RawPathSearch`、`PathFinalizeOps` 和路口合并都能改写 BAND 的路径。先用折返、宽路、保护缺口和路口捐赠夹具核对最终落列；再让位置、路宽和保护版本都相同的步骤复用精确采样。明确区分合法复用和需要重验的变动，保留桥头加密、长桥弯和局部避让；取消第二次松弛继续等真机 A/B。

## 已有证据排除的尝试

| 尝试 | 停止理由 |
|---|---|
| 用单点群系预筛决定要不要查结构 | 历史 37,181 个探测位置中，有 33,288 个会被预筛拒绝；其中 769 个有真实结构起点。不能复刻原版多点采样。 |
| 整套桥掩码逐列细采 | 83 段水 / 4,538 站，整站全湿 88.8%，仅一列湿 1.9%。先针对有证据的错桥修复。 |
| 对齐计价和建造阈值 | 历史 63 次过水中，只有 1 次落在差异区间 `(12,20]`。 |
| 给结构解析加记忆化 | 既有样本 `uniqueStarts == total`，未发现可利用的重复解析。 |
| 开回 GPU 精确采样 | 整合包的精确密度图超过当时 4060 的 2,046 MiB 单缓冲上限，`clCreateBuffer -61` 后回落 CPU，拖住生成。粗采 GPU 是另一件事。 |

长桥弯、村庄包围盒、路肩开关和存档协议属于现有[开发约定](../CONVENTIONS.md)。`crossing` 解耦须先拿到新的真机跨度召回数据；用户确认前保持现状。
