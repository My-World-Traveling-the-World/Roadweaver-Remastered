### 离线证据（不启动游戏就能看的）

- 8 个合成地形、40 站：**DP 可行 7 / DP 胜 5 / 旧胜 1 / 平 1**
- 土方量：`cut` 从 **85~193 → 0~30**（旧 pass 先按地形铺再夹坡，夹出的高差全变挖方）
- 陡坡（每站 +4）：旧解 **挖掉 3025 格方块**，新 DP 直接报不可行
- 模式感知：陡坡 +2/站 时用 **「1 座桥(8站) + 1 条隧道(19站)」** 解决 —— 旧代码注释里承认这类地形最难缠

## 五、★「别再犯」清单（我自己的 5 次误判 + 3 种失败形态）

这部分比成绩更值得读。

### 误判（改了判断，代码没动）

| # | 我曾判断 | 事实 |
|---|---|---|
| 1 | `promoteRuntimeBridges` 是"每区块重算"热点 | 它是 **O(窗口) 增量探测的安全网**，不能删 |
| 2 | `SegmentPaver.planGrade` 是"施工期重算"热点 | 插值仅 **约 2 万 flops/区块**，不是热点 |
| 3 | S1"桥范围只算一次" | 实际**每条路 2 次**；收益是"每区块 → 每条路" |
| 4 | 死代码守卫能覆盖方法级 | 只覆盖**类型**；方法级按名统计**误判率 80%** |
| 5 | `-Dorg.gradle.internal.instrumentation.agent=false` 修好了 daemon 连接 | **巧合**；后来带着该开关照样失败 |

### 失败形态（改坏了代码，已回滚）

| # | 形态 | 根因 |
|---|---|---|
| 1 | 拆配置界面产出 1754 行单类 | 花括号扫描**没按行重置行注释状态** |
| 2 | `SurfaceGradeLimits` 抽取报"定义了变量 LIMIT_LOGGER" | 新文件头**又声明了一遍 record** ⇒ 内层遮蔽 |
| 3 | `SurfaceGradeLimits` 抽取报"找不到 TUNNEL_MOUTH_OVERBURDEN" | 部分删除**把 javadoc 变成未闭合**，吞掉下一行 |

### 三条方法论

1. **间歇性故障上，「改一件事然后它好了」不构成因果证据** —— 必须先能复现。
2. **按名字统计"引用"对类型够用，对方法不够用**（`::method`、覆写、反射都不留名字痕迹）。
3. **任何基于括号配平/行号区间的 Java 改写，都要用 AST 或编译器自带结构** —— 手写扫描器在这个项目上已经错了两次。
