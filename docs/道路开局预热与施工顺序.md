# 道路开局预热与施工顺序

以下是新世界默认「粗采样＋走廊精修」的生产顺序。窗口可按失败情况扩展重试；不同路线允许并行，同一条路线仍按表中依赖执行。

| 顺序 | 阶段和子阶段 | 生产入口 |
| --- | --- | --- |
| 0 | 预读道路索引、施工台账。若装河流，先等河流发布就绪；若也装长城，再等长城发布可用的预热保护。前置失败本次不启动道路。 | `MinecraftServerMixin` → `RoadStartupGate` |
| 1 | 建立开局会话，以出生点设核心窗口和候选余量；读断点，复用仍匹配的结构、地形和道路缓存，恢复中断前未完成任务；按设置放出生小屋。 | `InitialGenManager.begin`、`RoadPlanningService.initialPlanAsync` |
| 2 | 预测并核实可接入的结构端点，加入合格的既有连线端点、去重，按距离上限建立拓扑候选。 | `AsyncPlanningOps.planRectRound`、`PipelinePlanner` |
| 3 | 拓扑选边：粗地形估算坡度与通行距离，测地最小生成树选边；保留穿过核心区的边，衔接已有网络，补允许的缺口，过滤玩家明确压制的连接。此时只有要连哪两端，尚未承诺施工线。0.9.107 曾在这里提前整域跑 CPU 精采。 | `PipelinePlanner.plan`、`ComponentConnector` |
| 4 | 按连线直廊预备结构避让快照，读或生成粗地形瓦片，计算每条粗走廊；按桥隧粗代价、坡度、水体和结构限制调整候选，协商共用跨河段，整理方向和中心线。 | `AsyncPlanningOps`、`CoarseCorridorPlanningAdapter.plan` |
| 5 | 以已求出的粗路线补查其真实走廊的建筑保护、登记计划缓存；可按触及窗口边缘和失败原因扩大窗口，再跑受影响的计划。按出生点、村庄入口、连接状态整理正式任务；一次集中预热这些走廊的联动河流数据。 | `AsyncPlanningOps.finishAdaptivePlan`、`InitialPlanWaiter`、`InitialGenManager.prewarmInitialRiverPlates` |
| 6 | 每条正式路线：取粗走廊，做局部精采样与 BAND 精修；后处理中心线（简化、局部平滑、桥段整理、补点、栅格化），形成实际道路宽度的施工站点，裁切结构附近的站点。 | `InitialRouteSubmitOps` → `Road` → `PathFinalizeOps` |
| 7 | 用走廊实际采样提取跨水与过路区间，求纵断面目标高度，复核桥面、桥头、隧道和安全坡度；按需重结算桥头与跨度，显式记保护缺口和已建道路复用段；存在可修失败时才进一步精修、重绑端点或选可接替路线。 | `Road`、`PathSpanExtractor`、`TargetYComputation`、`InitialPlanWaiter` |
| 8 | 批量合并新路口并对接已建网络；用最终占地体积复核水域、村庄、长城和树等保护；验收后才写道路站点、剖面、跨度、状态和区块索引，加入待回填队列。UI 的「道路后处理」主要在这里。 | `InitialRoutePersistOps`、`InitialPlanWaiter` |
| 9 | 已加载的 FULL 区块由队列回填，后续新生成区块也按计划施工。准备挖填与净空、铺整砖或半砖、按模板或桥梁构件落桥、建隧道；局部拒绝按原规则修复并重铺，随后放路灯路牌等装饰，最后登记已施工。不会为了整条路一次强加载全部区块。 | `DeferredInitialRoadConstructionService`、`ConstructionTransactionCursor`、`PathFeature` |

拓扑粗采样需要先取得端点，才能知道该查哪里；它为最终连线提供代价，和在确定连线后规划每条粗走廊是两步。同一步长、同维度和重叠区域可复用相同的粗瓦片。逐列精采样用于已收窄的走廊、桥隧判定和实际占地保护。

若主动选择了「全域精确」模式，`FullRegionPlanningAdapter` 仍会在求每条走线前做该模式要求的整域采样；这是显式策略，和旧版默认拓扑暗中精采是两件事。

H 地图读的是持久化的道路计划。计划已写、相邻区块已落块、整条路已施工是三个不同状态；用路面或桥面验收时，应同时查看对应区块的实际方块、计划占地与施工台账。
