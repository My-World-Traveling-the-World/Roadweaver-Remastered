# 道路开局预热与施工顺序

以下是新世界默认「粗采样＋走廊精修」的生产顺序。窗口可按失败情况扩展重试；不同路线允许并行，同一条路线仍按表中依赖执行。

| 顺序 | 阶段和子阶段 | 生产入口 |
| --- | --- | --- |
| 0 | 预读道路索引、施工台账。若装河流，先等河流发布就绪；若也装长城，再等长城发布可用的预热保护。前置失败本次不启动道路。 | `MinecraftServerMixin` → `RoadStartupGate` |
| 1 | 建立开局会话，以出生点设核心窗口和候选余量；读断点，复用仍匹配的结构、地形和道路缓存，恢复中断前未完成任务；按设置放出生小屋。 | `InitialGenManager.begin`、`RoadPlanningService.initialPlanAsync` |
| 2 | 预测并核实可接入的结构端点，加入合格的既有连线端点、去重，按距离上限建立拓扑候选。 | `AsyncPlanningOps.planRectRound`、`PipelinePlanner` |
| 3 | 拓扑选边：粗地形估算坡度与通行距离，测地最小生成树选边；保留穿过核心区的边，衔接已有网络，补允许的缺口，过滤玩家明确压制的连接。此时只有要连哪两端，尚未承诺施工线。0.9.107 曾在这里提前整域跑 CPU 精采。 | `PipelinePlanner.plan`、`ComponentConnector` |
| 4 | 按连线直廊预备结构避让快照，读或生成粗地形瓦片，计算每条粗走廊；按桥隧粗代价、坡度、水体和结构限制调整候选，协商共用跨河段，整理方向和中心线。 | `AsyncPlanningOps`、`CoarseCorridorPlanningAdapter.plan` |
| 5 | 以已求出的粗路线补查其真实走廊的建筑保护、登记计划缓存；可按触及窗口边缘和失败原因扩大窗口，再跑受影响的计划。按出生点、村庄入口、连接状态整理正式任务；一次集中预热这些走廊的联动河流数据。 | `AsyncPlanningOps.finishAdaptivePlan`、`InitialPlanWaiter`、`InitialGenManager.prewarmInitialRiverPlates` |
| 6 | 每条正式路线：取粗走廊，做局部精采样与 BAND 精修；后处理中心线（简化、局部平滑、桥段整理、补点、栅格化），形成实际道路宽度的施工站点，裁切结构附近的站点。 | `InitialRouteSubmitOps` → `Road` → `PathFinalizeOps` |
| 7 | 用走廊实际采样提取跨水与过路区间，求纵断面目标高度，复核桥面、桥头、隧道和安全坡度；按需重结算桥头与跨度，显式记保护缺口和已建道路复用段；存在可修失败时才进一步精修、重绑端点或选可接替路线。 | `Road`、`PathSpanExtractor`、`TargetYComputation`、`InitialPlanWaiter` |
| 8 | 批量合并新路口并对接已建网络；用最终占地体积复核水域、村庄、长城和树等保护；验收后才写道路站点、剖面、跨度、状态和区块索引，加入待回填队列。UI 的「道路后处理」主要在这里。 | `InitialRoutePersistOps`、`InitialPlanWaiter` |
| 9 | 已加载的 FULL 区块由队列回填，后续新生成区块也按计划施工。准备挖填与净空、铺整砖或半砖、按模板或桥梁构件落桥、建隧道；局部拒绝按原规则修复并重铺，随后放路灯路牌等装饰，最后登记已施工。不会为了整条路一次强加载全部区块。 | `DeferredInitialRoadConstructionService`、`ConstructionTransactionCursor`、`PathFeature` |

拓扑粗采样需要先取得端点，才能知道该查哪里；它为最终连线提供代价，和在确定连线后规划每条粗走廊是两步。同一步长、同维度和重叠区域可复用相同的粗瓦片。逐列精采样用于已收窄的走廊、桥隧判定和实际占地保护。

进入正式路线批次后，粗格、瓦片、有效避让快照与寻路参数未变时复用首次 BAND 解。若缺解或输入有变，则现场重算。河流分类、共桥协商、隧道提示和后续精采照常运行；客户端日志「开局粗寻路复用」分别记录复用与重算的求解次数。

若主动选择了「全域精确」模式，`FullRegionPlanningAdapter` 仍会在求每条走线前做该模式要求的整域采样；这是显式策略，和旧版默认拓扑暗中精采是两件事。

H 地图读的是持久化的道路计划。计划已写、相邻区块已落块、整条路已施工是三个不同状态；用路面或桥面验收时，应同时查看对应区块的实际方块、计划占地与施工台账。

## 2026-11-22 整链路复核

### 选边前的 CPU 精采从哪里来

旧仓冻结点 `2c6547a` 在 `RoadPlanningService.planPrimaryEdges` 按端点选边，再由 `CoarseCorridorPlanningAdapter` 在粗地形上寻路。重制版 `a1a887c`（11 月 13 日）第一次将测地 MST 接入生产 `PipelinePlanner` 时，就对候选范围调用了 `SampledTerrainField.fromAccurateSampler(AccurateHeightSampler.create(level), …)`；`70f9341` 让它成为唯一选边器。后来的分页改进延迟了大窗口的取样和分配，仍在求精确高度。`step=8` 是格点间距，无法把 CPU 的单列求值从精确变为粗略。

0.9.107 在 09:53:13 打印 `875×861 = 753375` 个工作集格点；现场线程栈落在 `PipelinePlanner → AccurateHeightSampler → NoiseChunkHeightSampler`，10:11:37 选边返回，整个拓扑 `1,105,385 ms`，包含取样与求解。`AsyncPlanningOps` 仅设置「扫描结构并准备连线」的端点总数，拓扑内没有完成回调，UI 的 `0/35` 不是结构扫描仍然一无所获。`0808d14` 已把生产入口换成可与后续走廊复用的 `CoarseTopologyGrid`。这一阶段仍然需要较大范围的**粗**取样和测地求解；默认不再整域求精确高度。

### 0.9.107 现场问题与后续修复目标

1. **让纵断面失败可复现、可定向修。** 在可行域收缩时保留首个冲突区间、端点锁高、桥底线、覆土、挖填和坡度上限，按连接传到终态和重试。先修已单独复现的负 Y 锁高：`TargetProfileSolver` 用 `-1` 标记无锁，`ProfileDpSource`、`ProfileDpSolver`、`ProfileFallback` 等又将负数视为无锁；用独立有效标记贯穿求解与修复，不改持久化。重放出生点东向路线，定位真实拒绝原因；对局部无解先试有界改线、重接端点或重选跨度，不能靠放宽硬约束发出坏路。
2. **用成品连接反馈选边。** 后处理和发布后单独统计完整连接、保护缺口和失败，按结构端点口径报告出生点连通分量。主边失败且拆分网络时，先从已有短候选里尝试有施工希望的替代边；保留保护范围，允许报告剩余缺口。
3. **缩小重复准备，有证据再调策略。** 0.9.110 先在同种子新世界记 BAND 的 `reusedSolves/recomputedSolves`，区分区域边界、瓦片、结构和巨树导致的重算；随后量结构准备的实际覆盖和候选起点数。结构起点以真实走廊补齐、逐步扩大时要与基准逐盒对拍，不能用已证明漏结构的群系预筛。精采 `22.79x` 是请求批形的列数比，`AccurateHeightSampler:250–272` 未扣除共享缓存命中，不是重复 CPU 耗时；整块样本还会被终态复用，先分别计真实后端求值与后续利用率。
4. **终态保护列按实际唯一 X/Z 计算。** `RoadConstructionVolumePlanner:281–288` 已把路幅列加进按列去重的施工集合；`FinalRoadStructureValidator:95–111,134–155` 又追加路幅并以列表条目计算区块分母，而分子是去重列。例：5 个实际列、其中 3 个缺采，若追加两条重复记录，整块比例分支从 `6>=5` 误变为 `6>=7`。统一去重边界后离线对拍相同实际占地、相同保护命中，以及稀疏／整块阈值；先同时记录唯一列和遍历次数。同一条路现场有累计 `cached=1121044`，它不是新增精采，也不是一百多万个唯一列。
5. **将 UI 和方块验收对齐。** 进度按「端点扫描→粗拓扑→粗寻路→走廊精修→终态验收→计划已发布」区分；选边没有可估的分母时显示已处理的实际工作或耗时，不能假装卡在 `0/35`。另记录实际区块施工、保护跳过、未加载或失败。实机对同一长桥取相邻 FULL 区块的完整横断面和台账；半砖坡、隧道比例和长桥投影已有离线保护，此轮尚无 0.9.110 新世界现场对照。

## 0.9.111 已完成的代码与下一次实机核对

- 选边开始显示「根据粗地形选择连线」与已经收集的端点数。选边未结束时显示阶段与耗时；没有工作总数就不编造百分比。重新扩大窗口扫描时清除上一轮计数。
- 负 Y 端点与桥面锚点照常锁高。仍无解时，`profileConflict=` 标出冲突站、限制站、上下界和类别；后续「没有局部路径」不抹掉这份见证。
- `[INITIAL-REALIZED-TOPOLOGY]` 用最终验收落盘的道路计划统计出生点分量；失败和受保护缺口不连通。确有高程失败且两端未连通，才允许一轮有限短补边，最多检查 8 条断边、启动 4 条候选；仍走普通精修和终态保护。补边不会把原断边标为完成。
- 终态精采只以唯一施工列决定逐列／整块批次。仍校验全部占地。源码未缩小结构准备覆盖；在同种子取得起点数、真实后端求值与耗时之前，不据此推算提速。

同种子新世界先查出生点向东的 `(-32,-208)→(832,304)`、计划分量和楼桥处的保护缺口；再给东侧跨海桥定坐标，核对相邻 FULL 区块的施工台账和实际走面。六段旧版记录只重放了地表高度，仍无解，不能替代本版整链路与桥隧复验。详细守卫及部署记录见[交接台账](HANDOFF.md)。
