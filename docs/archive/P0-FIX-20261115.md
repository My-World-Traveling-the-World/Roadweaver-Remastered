## P0-1｜一条道路文件瞬时读不到 ⇒ 索引被永久改写

### 核实结果：成立（代码链路 + 复现双证）

`RoadChunkStore` 的读失败路径：

| 行 | 行为 | 问题 |
|---|---|---|
| `:416-424` | `catch (IOException) { skippedEntry = true; continue; }` | **瞬时读失败 = 当成「这条没了」** |
| `:457` | `skippedEntry` ⇒ `rewriteMetadata = true` | 把「读不到」混进「元数据要修」 |
| `:325` | `if (rewriteMetadata && !readOnlyDegraded) persistSnapshot(...)` | **改写 index.json** |
| `:449` | `RoadSnapshot.fromEntryMap(entries)` | 用的是**已剔掉失败条目**的部分快照 |

**根因是不对称保护**：同文件 `:299-321` 的 `readOnlyDegraded` 只保护
「**整个索引**读失败」，注释写得很好——「IO 失败不代表数据不存在，恰恰最不该把它当成空库」——
但「**单条** NBT 读失败」只是循环里一个 `continue`，没走这条保护。

`skippedEntry` 一共有 7 个设置点，只有 `IOException` 那一个是「不知道数据在不在」；
其余（索引项残缺、越界引用、`road == null`、`normalizeLegacyRoad` 返 null、指纹退化、指纹不符、
`RuntimeException`）都是「**已知这条不可用**」——那些拿部分快照修元数据是安全的。

### 修法（最小面：不动存档格式、不动读路径）

1. `LoadedSnapshot` 加第 4 字段 `readFailure`，**只在 `IOException` 那一支**置真
2. 载入完成后：`if (readFailure && !readOnlyDegraded) { readOnlyDegraded = true; LOGGER.error(...) }`
3. 复用**已有且已被测试覆盖**的写拒绝机制 ⇒ 所有写路径自动拒绝

读路径不变：故障期间查询仍用部分视图（不崩），索引保持原样，
下一次能完整读出时自然恢复。

### 验证（用审计方自己的复现手法，真 Windows 文件锁）

| | 故障期间 | 解锁后重开 | 索引 |
|---|---|---|---|
| 修复前 | 1 条 | **1 条（永久丢失）** | 被改写 |
| 修复后 | 1 条 | **2 条** | **逐字未变** |

探针输出：`IO fault=FileSystemException` → `FIX OK: index untouched during read fault`
→ `P0-1 FIXED: saved=2 whileFault=1 afterUnlock=2 indexIntact=true`
拿 HEAD 版本跑同一探针：`AssertionError: P0-1 NOT FIXED`（证明探针有判别力）。

**已固化为永久回归** `RoadChunkStoreReadFaultTest`（含「故障是否真的注入成功」的自检，
防夹具失效导致断言恒真）。负控：禁用修复那一段 ⇒ 该用例红。
**平台限制**：故障注入用 Windows `NOSHARE_READ`，非 Windows 上 `assumeTrue` 跳过 ⇒ 那里不提供保护。

## P0-2｜隧道覆土方向算反 ⇒ 该埋的隧道被抬到地表上方

### 核实结果：成立，而且现有测试把错误固化成了契约

| 位置 | 代码 | 方向 |
|---|---|---|
| `ProfileDpSource:154` | `cap = terrainY - minCover` → `hi[i] = cap` | **上界** ✅ |
| `ProfileFallback:76`（修前） | `lower = max(lower, terrainY + cover)` | **下界** ❌ |

覆土（cover）的物理含义是「隧道顶上方要有这么多土」⇒ 隧道必须**低于**地表至少 cover 格。
修前却是「高于地表 cover 格」，那是悬空天桥。

审计方实测：地表 80 / 覆土 4 ⇒ DP 全 76，回落全 84，**回落自带的坡度检查报零违规**
（它只量坡度，不量覆土方向）。回落结果被 `TargetYComputation` 的两个失败入口直接当合法纵断面用。

**更糟的是**：`ProfileFallbackTest:69-77` 原本断言 `h[5] - terrain[5] >= 3`
（路面应高于地表 3 格）——**把缺陷写成了契约**，于是「只改符号」会让这条跑红，
看起来像是修复破坏了正确行为。

### 修法

`ProfileFallback` 改成与 `ProfileDpSource` 同契约：

```java
int coverCap = terrainY[i] - cover;      // 覆土是硬要求 ⇒ 上界
upper = Math.min(upper, coverCap);
if (lower > upper) lower = upper;        // 与 DP 一致：让步的是最大挖方
```

测试侧：把那条固化错误的断言**改正**（不是删掉），并补两条——
「覆土与最大挖方冲突时让步的是挖方」、「隧道站绝不允许被抬到地表以上」。

### 验证

负控：把符号改回旧的下界写法 ⇒ **3 条用例红**。
