# 开发现状

源码基线 `4f1923a`（2026-11-16），Windows / JDK 21 全量回归 `PASS tests=1201 skipped=0 aborted=0 failed=0`，Fabric 编译通过。更新记录和负控详见[交接台账](HANDOFF.md)。[发布台账](RELEASES.md)里的版本有独立的源码和验证边界。

**跨模组负载协作。** 已只读核对 AutoTune、Chunky、HyperSpeed、Twilight 传送、Streams 和 C2ME QoS 六个相邻工程。道路普通预算与显式保护已从只认两个来源改为聚合现有 API 注册表，保留上下文、零 lane、故障隔离和预热/独占进展规则；没有新增总调度器或修改外部工程。C2ME QoS 当前源码仍走内部类反射，不能写成整组迁移已完成。道路启动诊断已停止询问有状态的线程建议，避免日志的未知参数把 Chunky 预算写回 1。API 接线的离线守卫不代表并行流、INITIAL 子任务或 4096 工作集已受控；职责和边界见[架构](../ARCHITECTURE.md#跨模组资源协调)。

**配置和 UI。** 地图复用同快照最近两档折线，平移每帧仍查视口；Xaero 实际叠图与帧时待测。旧势场 A* 的部分配置键仍为了兼容保留；界面标记不生效。客户端直连部分业务实现是存量债务，新增跨层依赖由架构守卫约束；旧版 UI 真机验证不能代替当前界面验收。

**开局范围与游玩负载。** 开局半径上限独立放宽到 4096 区块，默认仍为 128；动态半径上限仍为 2048，地图 AOI 不随开局上限放大。4096 对应出生点周围约 131072×131072 格的核心范围，只是可配置范围，尚无该规模的安全或耗时验收。现有候选面积守卫只缩外扩余量，不能限制核心本身的总工作量。游玩调度已有前台压力暂停及预算，但 CpuAccurateHeightBackend 的并行流和 CoarseCorridorPlanningAdapter 的 INITIAL 子任务未统一受游玩预算约束；不能把 gameplayThreadCap=2 理解成所有采样/寻路加起来最多两线程。下一步优先补这些边界，详见路线。

**性能证据的范围。** 区块编译按扩张包围盒交区块扫描，路权匹配按 X/Z 分桶；FMM 已对拍新旧堆的格值和点序，远目标离线夹具的每次分配中位数从 4.49 MB 降至 2.28 MB。[交接历史](archive/HANDOFF-ROUNDS-00-12.md) 第 3、4、9 轮有样本和耗时。这些数据不代表进档速度、TPS、帧时间或区块尾延迟。

**计时接线。** 隧道探测与建造、路灯选座、施工台账和 Chunky 就绪扫描/写入已有可选诊断。开关默认关闭；先按[验证手册](VALIDATION.md)采样，再决定是否改探测或写盘策略。

**对照基线。** 旧版用来核查可见能力和再现退化；历史 57 次真机观测和旧发布件只说明当时采样，当前二进制仍需[刷新样本](VALIDATION.md)。
